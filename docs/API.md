# QueryDoc AI — REST API (v1)

**Author:** Raahul Sallagunta

Base path `/api/v1`. Interactive docs: `http://127.0.0.1:8000/api/docs` (Swagger UI),
`/api/redoc`, machine-readable spec `/api/openapi.json` (generated by FastAPI from the
Pydantic schemas in `backend/app/schemas/api.py`).

> **Security model:** local, single-user. There is no authentication. CORS allows only the
> configured origins (default: the Vite dev server). Do not expose the server publicly.

## Conventions

- JSON request/response bodies; uploads are `multipart/form-data`.
- Every response carries `X-Request-ID` (echoed if the client sends one); the same id appears in the JSON logs.
- Errors always look like:

```json
{ "error": { "code": "duplicate_document", "message": "'a.pdf' is already in the library as 'a.pdf'.", "details": { "document_id": "7576edb531d98488" } } }
```

| HTTP | `code` examples | When |
|---|---|---|
| 400 | `no_documents`, `bad_request` | No indexed documents; engine-level bad input |
| 404 | `document_not_found`, `conversation_not_found`, `not_found` | Unknown or malformed id |
| 409 | `duplicate_document`, `document_busy`, `document_not_ready`, `incompatible_settings` | Conflicts with current state |
| 410 | `file_missing` | Re-index requested but the original PDF is gone |
| 413 | `file_too_large`, `invalid_pdf` (size) | Upload above `QUERYDOC_MAX_UPLOAD_MB` |
| 415 | `unsupported_type` | Not a `.pdf` |
| 422 | `validation_error`, `invalid_pdf`, `invalid_settings`, `password_protected` | Schema / content validation |
| 429 | `generation_queue_full` | More than `max_active + max_queue` generations waiting |
| 503 | `generation_timeout`, `model_unavailable` | No slot in time / model cannot load |
| 504 | `timeout` | Request exceeded its timeout |

## Documents

| Method | Path | Description |
|---|---|---|
| POST | `/documents/upload` | Upload 1–20 PDFs (`files` field). Validates synchronously (type, magic bytes, size, duplicates) and returns **202** with `{documents: [...], errors: [...]}`; extraction, chunking, embedding and indexing continue in the background. With one file, validation failures are returned as an HTTP error; with several, per-file errors are listed and valid files proceed. |
| GET | `/documents?q=&status=` | List, newest first; optional filename/title filter and status filter (`queued|processing|ready|failed`). |
| GET | `/documents/{id}` | One document (pages, chunks, chunking config, stage timings, embedding throughput, scanned pages). |
| GET | `/documents/{id}/status` | Lightweight `{status, stage, progress, error}` for polling. Stages: `queued → starting → extract → embed → done → ready` (or `failed`). |
| GET | `/documents/{id}/file` | The stored PDF (`application/pdf`, inline). The path is derived from the validated 16-hex id only. |
| DELETE | `/documents/{id}` | **204.** Removes vectors (FAISS), chunk metadata, stored PDF and the DB row. 409 while processing. |
| POST | `/documents/{id}/reindex` | **202.** Re-chunks and re-embeds with the *current* chunking settings. |

`id` is the first 16 hex characters of the PDF's SHA-256, so identical bytes always map to the same document.

## Chat

### POST `/chat` — blocking

Request (`ChatRequest`):

```json
{
  "message": "How long can an AAL3 session stay idle?",
  "conversation_id": null,
  "document_ids": ["ccfce7510a126793"],
  "regenerate_of": null,
  "top_k": 5, "use_rerank": true, "use_hybrid": true, "max_new_tokens": 256, "temperature": 0
}
```

- `document_ids`: scope. Omitted/empty on a new conversation = all ready documents; omitted on an existing conversation = that conversation's scope. Unknown ids → 404, not-ready → 409.
- `conversation_id`: continue a conversation; earlier generated turns are used to interpret follow-up questions (retrieval query and prompt), facts must still come from sources.
- `regenerate_of`: an assistant message id; it is replaced by a new answer to the same question.

Response: `{conversation_id, user_message, message}` where `message` (`MessageOut`) contains `content`, `status` (`verified | partially_verified | unverified | insufficient_evidence | retrieval_only | cancelled | error`), `citations[]` (`tag, chunk_id, doc_id, source, page_start, page_end, excerpt, retrieval_score, support, method: model|attributed`), `sources[]` (ranked passages with `scores` — `dense`, `bm25`, `rrf`, `rerank`), `notes[]`, `timings_ms` (`queue_wait, retrieval, prompt, generation, time_to_first_token, citation_check, total`).

### POST `/chat/stream` — Server-Sent Events

Same request body. Response `text/event-stream`:

```
event: meta
data: {"conversation_id": "...", "user_message": {...}, "document_ids": ["..."]}

event: retrieval
data: {"sources": [...], "latency_ms": 81.4}

event: token
data: {"text": "Reauthentication "}
...
event: done
data: {"conversation_id": "...", "message": { ...MessageOut, verified... }}
```

or `event: error` with `{code, status, message}`. Comment lines (`: keep-alive`) are sent every 10 s while waiting. **Closing the connection cancels generation** at the next token; the partial answer is stored with status `cancelled`. Validation errors (unknown conversation, no documents, bad scope) are returned as normal HTTP errors *before* the stream starts.

## Settings

| Method | Path | Description |
|---|---|---|
| GET | `/settings` | `{settings, options, restart_required}`. `options` lists allowed models, devices available on this machine, and whether the embedding model is locked. |
| PUT | `/settings` | Partial update (unknown fields → 422). Validated as a whole: chunk size 200–2000, overlap ≤ size/2, `fetch_k ≥ top_k`, `rerank_k ≥ top_k`, tokens 16–1024, temperature 0–1.5. Devices must exist on this machine (409). Changing the embedding model while documents exist → 409. `performance_mode` applies a preset (`quality`: rerank 30, `balanced`: rerank 20, `speed`: no rerank) unless fields are given explicitly. Settings persist in SQLite and are re-applied on restart. |

## Analytics

| Method | Path | Description |
|---|---|---|
| GET | `/analytics/overview` | `source: "runtime"` — telemetry recorded by this installation: document counts, index size, query counts by outcome, retrieval/generation/TTFT/total p50/p95 over the last 500 questions, recent query series, per-document ingestion timings, process RSS and peak RSS, model status. |
| GET | `/analytics/benchmarks` | `source: "benchmark"` — condensed results read from `results/*/results.json` (relevance, retrieval latency GPU/CPU, embeddings memory, concurrency, generation, ingestion, API end-to-end), each with provenance (`command, timestamp, git_commit, hardware, swap_used_gb`). |

## Health

GET `/health` → `{status: ok|degraded, version, models: {embedder, reranker, llm}, documents, index_vectors, ingestion_queue}`. `degraded` means the LLM failed to load (answers fall back to retrieval-only).

## Example session (curl)

```bash
curl -F "files=@data/corpus/NIST.AI.100-1.pdf" http://127.0.0.1:8000/api/v1/documents/upload
curl http://127.0.0.1:8000/api/v1/documents/7576edb531d98488/status
curl -N -X POST http://127.0.0.1:8000/api/v1/chat/stream -H 'Content-Type: application/json' \
     -d '{"message":"What are the four functions of the AI RMF core?"}'
```
